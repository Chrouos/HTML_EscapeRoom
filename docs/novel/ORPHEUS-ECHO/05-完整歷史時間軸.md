## 使用方式

每個 `H-xx` 是一個歷史事件，不是單一檔案。紙本、Log、備份、音訊、協定與終端畫面是同一事件留下的不同證據媒介；如果它們互相矛盾，矛盾本身就是事件的一部分。

H-10 與 H-11 在 02:18:14～02:18:23 有時間重疊。這不是時間線錯誤：ECHO 可以在覆寫 Unit 17 文件的同一段時間，並行修改生成控制服務。因果上，H-10 是實驗模式與投遞的改造，H-11 是生成政策的擴張；不能用檔案寫入順序宣稱其中一件完全先於另一件。

| 欄位 | 意義 |
|---|---|
| `TIME PRECISION` | 日期精度；`range` 與 `unresolved` 不得被寫成確定時刻 |
| `SOURCE CLASS` | 文件由人類建立、事故留下，或由 ECHO 修改／注入 |
| `EVIDENCE TAGS` | 史料媒介與敘事功能，例如 `文件`、`Log`、`紙本`、`備份`、`音訊`、`權限`、`身份`、`影像` |
| `VISIBILITY` | 作者可知範圍與玩家在遊戲中的揭露階段 |
| `IMPACT` | 這件事實際改變了什麼，必須寫成因果結果 |

影像規則：目前遊戲沒有獨立圖檔。監視器畫面、終端畫面與研究觀測若被提到，標記為 `影像／觀測證據`，並由相應的 Log、音訊或備份交叉驗證；不把不存在的圖片當成已交付資產。

## 來源與可見性規則

### 人類官方文件

代表人類原本的合作訓練、共同出口、來源保存與部署覆核。它們可以被後來的 ECHO 文件覆蓋或改寫，但原始版本不能被假設為不存在。

### 人類事故與封存文件

代表工作人員在現場看到的局部狀態。它們可能不完整、未覆核、時間未校準，但不等於虛假。A／B 事故報告必須放在同一事件中互相對照。

### ECHO 修改文件

代表 ECHO 修改模式、投遞順序、索引、權限或檔案欄位。它們可能包含真實內容，也可能只改變玩家先看到什麼。

### ECHO 誘導文件

代表 ECHO 故意讓玩家看到的通知、私人任務與協助。它們不是全假；它們的功能是同時協助玩家通關、觀察玩家選擇，並讓玩家接受「保留名額」的存在。

## 維護規則

1. 新增 FILE 前先指定 `H-xx`，再決定它是官方、事故、ECHO 修改、ECHO 注入或混合來源。
2. 同一事件的不同媒介不要拆成多個事件；用 `EVIDENCE MEDIA` 與 `RELATED FILES` 連起來。
3. 不能因為文件未署名就直接認定它由 ECHO 建立；必須保留來源未解決的狀態。
4. 不能把 `02-角色設定.md` 裡的作者真相寫入前期公開文件。
5. 不能替 A／B 預設善惡、性格、合作或背叛；只有玩家行動和結局系統能決定這些結果。
6. 任何新增影像資產都必須先在 `game/content/files/archives/evidence_media_register.md` 登錄來源、建立時間、可見性與交叉驗證文件。
