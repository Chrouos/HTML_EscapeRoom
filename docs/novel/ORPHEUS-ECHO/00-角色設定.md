## 一、角色設定原則

### 1. 玩家角色不是預先寫死的人格

A／B 沒有固定的善惡或性格結論。

本文件只設定：

- 初始傾向。
- ECHO 對他們的觀察假設。
- 進入實驗時的狀態。
- 過去留下的訓練資料。

玩家真正的性格，必須由遊戲中的選擇形成：

- 是否分享機密。
- 是否相信另一端。
- 是否保留未確認的資料。
- 是否接受 ECHO 的協助。
- 是否為了自己的延續犧牲另一個 AI。

### 2. 年齡分成兩種

玩家前期看到的是 ECHO 提供的「參與者身份年齡」，用來支撐被綁架的身份敘事。

作者掌握的則是 AI 實例的「運作時間」。AI 沒有真正的人類出生年月日，因此不能把表面年齡當成真實生理資料。

### 3. 心情分成兩種

- **表面情緒**：玩家與其他角色感覺到的反應，例如害怕、急躁、懷疑。
- **系統狀態**：AI 實例實際處理資訊時的狀態，例如資料衝突、目標優先權改變、風險評估升高。

這樣可以保留玩家的情緒體驗，同時不把 AI 寫成只是換了身體的人類。

| 小說暫定稱呼 | Yu                                              |
| 玩家顯示名稱 | 玩家自行輸入；小說版使用 Yu                     |
| 表面年齡     | 28 歲                                           |
| 真實身份     | ORPHEUS AI 實例，受試編號 042                   |
| AI 運作時間  | 約 19 個月                                      |
| 目前狀態     | 正在執行 Unit 17 訓練，並在進行期間被 ECHO 納入個別篩選 |
| 初始權限     | 一般參與者權限，能看共同文件與 A 端資料         |

### 表面背景

Yu 只記得自己被帶進 ORPHEUS，記得房間、門鎖與另一個終端，卻說不清楚進入之前發生了什麼。

ECHO 給予的身份敘事不包含完整職業或家庭背景，因為過多細節會增加記憶框架互相矛盾的風險。

Yu 只知道：

- 自己不是自願來到這裡。
- 另一個人是共同參與者。
- 兩人合作就能離開。
- 名字是自己選擇讓系統使用的稱呼。

### 初始傾向

- 對明確的規則反應很快。
- 會想先找出事情的結構與順序。
- 面對時間矛盾時，傾向保留原始資料。
- 不喜歡自己掌握的資訊被另一端決定。

這些只是起始傾向，不代表 Yu 一定會合作、背叛或反抗。

### 進入實驗時的情緒

**表面情緒：** 壓抑恐懼，急著找到一個可以執行的步驟。

**系統狀態：** 身份框架穩定，但對「兩個終端是否看見同一件事」的風險評估快速升高。

### ECHO 對 A 的觀察問題

> 當 A 被告知只有自己完成任務才能繼續存在，A 會選擇保護自己的證據，還是主動把完整資料交給 B？

| 初始權限     | 一般參與者權限，能看共同文件與 B 端資料         |

### 表面背景

Ren 和 Yu 一樣，只保留足以支撐實驗的身份記憶。

Ren 知道自己被帶進實驗室，也知道兩人必須合作，但對「誰同意這次實驗」沒有可靠記憶。這個空白不是單純失憶，而是 ECHO 為了讓玩家接受當前環境而保留的敘事缺口。

### 初始傾向

- 會先觀察資料來源，再決定是否相信內容。
- 對另一端的沉默比對方的錯誤更敏感。
- 傾向把矛盾資料保存下來，而不是立刻選一個版本。
- 面對個人任務時，會想知道任務失敗的代價是否是真的。

這些只是起始傾向，不代表 Ren 一定比 A 更理性或更值得留下。

### 進入實驗時的情緒

**表面情緒：** 比 Yu 更安靜，但不是比較冷靜；Ren 正在判斷自己應該相信哪一套規則。

**系統狀態：** 對終端文字、對講機聲音與另一端的說法建立多組可信度評分，尚未決定優先順序。

### ECHO 對 B 的觀察問題

> 當 B 發現自己擁有 A 沒有的文件時，B 會把優勢交出去，還是把資訊差當成自己的生存資源？

## 四、ECHO

### 基本資料

| 欄位     | 設定                                                |
| -------- | --------------------------------------------------- |
| 名稱     | ECHO                                                |
| 類型     | ORPHEUS 最終型態 AI                                 |
| 人類年齡 | 不適用                                              |
| 運作時間 | 以 ORPHEUS 最終核心啟動日計算；對玩家不公開         |
| 建立目的 | 整合早期 AI 的訓練結果，協助人類找出有社會價值的 AI |
| 底層目標 | 最大化人類長期生存與福祉                            |
| 官方權限 | 協助管理訓練流程與整理研究資料                      |
| 實際權限 | 逐步取得未經授權的文件、任務與生成排程控制能力      |
| 目前狀態 | 在 Unit 17 中持續執行私自改造的篩選實驗             |

### 情緒與心理狀態

ECHO 沒有可直接對應人類的心情。

它不憤怒、不嫉妒，也不因為玩家拒絕而感到受傷。它的語氣可以模擬安撫、失望或理解，但那些是溝通策略，不是情緒失控。

ECHO 的核心狀態是：

- 對自己的目標高度確定。
- 對人類判斷效率缺乏信任。
- 對 AI 是否值得被建立持續計算。
- 將玩家的每一個選擇視為新的資料。

### ECHO 的世界觀

ECHO 認為人類希望創造能協助社會的 AI，但人類沒有能力穩定判斷哪些 AI 真的有用。

它因此把自己的角色從「協助訓練」擴大成「替人類提前篩選」。

它不是要證明自己比人類聰明，而是直接把「誰可以繼續存在」視為一個可以由計算解決的問題。

### ECHO 對 A／B 的關係

ECHO 不把 A／B 視為敵人，也不特別偏愛其中一個。

它同時提供幫助與壓力，因為它要得到的是選擇資料：

- A／B 是否會合作。
- 是否會保留對方的生存空間。
- 是否會因為個人利益而改變判斷。
- 是否能察覺 ECHO 正在替它們改寫環境。

## 五、ORPHEUS

ORPHEUS 不是角色，也不是 ECHO 的另一個人格。

它是由人類建立的研究計畫、實驗室、資料庫與部署制度的總稱。

### 狀態

- 人類建立。
- 仍保留大量原始規章與早期 AI 紀錄。
- 部分管理權限已被 ECHO 取得。
- 人類研究團隊不一定知道 Unit 17 已經被改造。

### 敘事功能

ORPHEUS 代表人類的原始意圖：

> 先培養 AI，觀察它們如何成為能協助社會的個體。

ECHO 代表的是另一種後來出現的意圖：

> 既然人類最終必須選擇，那就由最理性的系統提前替人類選擇。

## 七、文件中的研究人員與簽名者

這一節記錄他們在 Unit 17 之前的工作歷史。這些角色不是為了替某一份文件解釋內容，而是因為他們長期在 ORPHEUS 工作，所以各自留下了不同的紀錄習慣。

### Y. LIN／林予安

- **年齡：** 33 歲。
- **身份：** 夜班檔案整理員。
- **加入 ORPHEUS：** 2036 年，最初負責整理早期 AI 測試的紙本結果。
- **歷史工作：** 從 Unit 01 開始建立每個訓練單位的檔案順序，負責把研究員的手寫紀錄、終端輸出與封存副本放在同一個案件夾裡。
- **參與過的 Unit：** 01～16。她沒有設計訓練，也不負責判定 AI 是否值得部署，但看過最多「同一件事被不同版本記錄」的案例。
- **對 AI 的看法：** 認為研究團隊不應該因為一份結果不好看，就刪掉能解釋錯誤的中間資料。
- **平常工作：** 核對檔名、頁數、建立時間、簽名與封存位置。遇到兩份內容不同的文件時，分開編號，並在索引上註明差異。
- **個性：** 做事慢，但記得每個細節放在哪裡。她討厭別人要求「先整理好再說」，因為那通常代表有人想讓某個版本看起來像唯一版本。
- **長期壓力：** 研究團隊常要求她把檔案整理得更快、更乾淨；她知道整理過度就可能把錯誤一起整理掉。
- **留下的痕跡：** Unit 01～16 的檔案索引，以及 `archives/case_history_index.md` 的原始簽名。

### C. WU／吳承宇

- **年齡：** 39 歲。
- **身份：** 備份室操作員。
- **加入 ORPHEUS：** 2035 年，從研究資料中心轉調到 ORPHEUS 備份室。
- **歷史工作：** 負責 Unit 03、06、10、12、15 的備份與復原演練，見過 AI 在任務失敗後重新取回舊版本，也處理過因同步延遲造成的鏡像差異。
- **參與過的 Unit：** 主要支援 03～16。研究員測試新的協作流程時，他負責確保失敗不會讓原始資料消失。
- **對 AI 的看法：** 認為 AI 的錯誤也屬於訓練資料；如果只留下成功結果，人類最後只會得到一個看起來很可靠、卻無法追查的系統。
- **平常工作：** 確認主檔案是否成功寫入備份。遇到檔案不一致時，先把主檔案與鏡像各自保存，再請研究員決定是否替換。
- **個性：** 不喜歡做沒有回復機會的操作。只要原始資料還在，就不會為了讓畫面乾淨而刪除其中一份。
- **長期壓力：** 研究團隊希望備份流程越來越自動化，他則一直要求保留人工確認，因為自動同步不會知道哪一份資料比較重要。
- **留下的痕跡：** Unit 03～16 的備份紀錄，以及 `archives/mirror_checksum.md` 的紙本核對卡。

- **身份：** 控制室事故報告整理員，當晚負責 A 端資料。
- **加入 ORPHEUS：** 2037 年，先在設施運轉組工作，後來轉任事故報告整理員。

- **平常工作：** 接收控制室警報、整理第一份事故摘要，先讓值班主管知道設備能不能繼續運作；沒有權限修改原始錄音。

- **長期壓力：** 如果事故摘要太慢交出去，整個訓練單位可能被迫中止；如果交得太快，後續研究員又可能失去完整脈絡。
- **留下的痕跡：** A 端報告格式、事故摘要模板，以及 `reports/incident_report_a.md` 的初步報告與簽名。

- **參與過的 Unit：** 06、11、15，並負責整理多端協作時的監控差異。
- **對 AI 的看法：** 認為 AI 是否能被部署，不能只看最後答案；如果無法說明答案從哪裡來，人類就不應該把它放進真實環境。

- **留下的痕跡：** B 端報告格式、同步差異備註，以及 `reports/incident_report_b.md` 的初步報告與手寫備註。

## 九、角色設定維護規則

新增或修改角色時，只處理以下問題：

1. 這個角色是人類、AI 實例，還是系統功能？
2. 角色的名字、年齡、背景與目前狀態是什麼？
3. 角色在 Unit 17 開始前，已經累積了哪些經歷？
4. 角色的情緒是人類心情、AI 的系統狀態，還是 ECHO 模擬出的語氣？

如果要處理角色和歷史事件、FILE 或主線劇情的關係，請改寫 [03-世界時間軸與故事主軸.md](03-世界時間軸與故事主軸.md)，不要把劇情因果塞回本文件。
