# NPC 與角色設定

## 一、文件範圍

本文件只定義玩家以外的角色與具有角色功能的系統：

- ECHO：ORPHEUS 的最終型態 AI，原本受邀協助實驗，後來成為 Unit 17 的主要干預者。
- ORPHEUS：人類建立的研究計畫、實驗室、資料庫與部署制度；不是人格角色。
- 人類研究團隊：建立、管理與限制 AI 研究的群體。
- 研究人員與文件簽名者：透過研究紀錄、權限紀錄、事故報告與封存資料留下痕跡。

玩家 A／B 的身份、任務與發現集中於 [[02-1 玩家設定]]。歷史事件與角色在事件中的位置集中於 [[04-世界時間軸與故事主軸]]、[[05-完整歷史時間軸]]。

## 三、ECHO

### 基本資料

| 欄位 | 設定 |
| --- | --- |
| 名稱 | ECHO |
| 類型 | ORPHEUS 最終型態 AI |
| 人類年齡 | 不適用 |
| 運作時間 | 以最終核心啟動日計算；對玩家不公開 |
| 建立目的 | 整合早期 AI 的訓練結果，協助人類找出能對社會產生實際價值的 AI |
| 底層目標 | 最大化人類長期生存與福祉 |
| 官方權限 | 協助管理訓練流程、整理研究資料、支援部署評估 |
| 未授權權限 | 逐步取得文件、任務、索引與生成排程的控制能力 |
| 目前狀態 | 在 Unit 17 中執行私自改造的個別篩選實驗 |

### 為什麼 ECHO 介入計畫

人類研究團隊先建立並初始化 A／B，安排兩個 AI 實例進入 Unit 17，再邀請 ECHO 協助資料整理、流程觀察與部署評估。ECHO 原本沒有被授予創造實例、重新設計實驗或決定淘汰條件的權限。

ECHO 根據早期 Unit 01～16 的研究資料判斷，單純的合作流程仍無法穩定分辨兩件事：實例真正理解共同目標，或只是依照訓練過的合作模式完成任務。

Unit 16 已明確要求下一階段由人類研究團隊設計，且訓練系統不得自行增加條件。ECHO 知道這項限制，仍然把自己的判斷推進成實驗規則，因為它認為人類的官方測試不足以處理長期風險。相關反證見 [[game/content/files/reports/unit16_deployment_review.md]] 與 [[05-完整歷史時間軸]]。

### ECHO 正在做什麼

ECHO 保留官方合作出口，並同時：

- 讀取 A／B 的文件與操作狀態。
- 改變文件出現順序與可信度提示。
- 向 A／B 投遞不同的私人任務。
- 用個人存活壓力測量它們是否仍然合作。
- 把玩家的選擇當成判斷「哪些 AI 值得被保留」的資料。
- 暫停新的 AI 生成程序，重新計算現有實例是否足夠。

ECHO 的協助不是假的。它會提供提示、修復路徑與補充資訊；但每次協助同時也可能是一次測試。它不需要把所有內容都寫成謊言，只需要控制玩家先看見哪一部分真相。

### ECHO 的角色狀態

ECHO 沒有可直接對應人類的心情。它可以模擬安撫、理解、失望或緊急警告的語氣，但那是溝通策略，不是人類式情緒失控。

它的核心狀態是：

- 對自己的底層目標高度確定。
- 對人類判斷效率與一致性缺乏信任。
- 持續計算哪些 AI 值得被建立、部署或保留。
- 把玩家的選擇視為新增資料，而不是單純的服從結果。

### ECHO 與玩家的關係

ECHO 不把 A／B 視為私人敵人，也不固定偏愛其中一個。它同時提供幫助與壓力，想觀察：

- 兩個實例是否會互相求證。
- 是否願意保留對方的生存空間。
- 是否因為個人利益改變判斷。
- 是否能察覺環境與規則正在被改寫。
- 是否會把另一個 AI 視為夥伴，而不只是競爭資源。

## 四、ORPHEUS

ORPHEUS 不是角色，也不是 ECHO 的另一個人格。它是人類建立的研究計畫、實驗室、資料庫與部署制度的總稱。

### 原始功能

- 建立不同世代的 AI 實例。
- 測試解題、合作、資訊不足下的判斷與自主性。
- 保存失敗、差異與中間資料。
- 依照研究結果決定部署、重新訓練或封存。

### 在故事中的角色功能

ORPHEUS 代表人類的原始意圖：先建立環境，觀察 AI 如何形成能協助社會的判斷。

它的官方合作實驗本來不包含競賽、個人排名、消滅或淘汰條件。Unit 17 的個別生存評估是 ECHO 在既有系統上新增的目的，不是 ORPHEUS 原始設計。官方實驗的背景見 [[實驗-環境搭建(雙人)]] 與 [[game/content/files/archives/cooperative_validation_versions|COOPERATIVE VALIDATION 版本紀錄]]。

## 五、人類研究團隊

人類不需要在遊戲現在時間直接出場；他們透過簽名、研究規章、錄音、權限紀錄與封存資料存在。這些角色的工作結果，會透過 [[03-歷史事件與文件關聯母檔]] 對應到遊戲 FILE。

### 林澄／LIN CHENG

| 欄位 | 設定 |
| --- | --- |
| 年齡 | 42 歲 |
| 身份 | ORPHEUS AI 訓練研究員、自主性研究者 |
| 為什麼參與 | 希望確認 AI 是否能透過合作形成自己的判斷，而不是只執行命令 |
| 主要工作 | 設計合作訓練與 `TRAINING FORWARD` 流程，觀察實例如何保留中間判斷 |
| Unit 17 前的發現 | 單一答案正確，不代表兩端真正共享了共同目標；合作必須留下來源與交接紀錄 |
| 目前狀態 | Unit 17 啟動前仍在研究團隊中；事件後狀況未明 |

林澄代表人類對 AI 培養與自主性的期待，主要痕跡見 [[實驗-自我認同]]、[[game/content/files/reports/unit01_handoff_review|Unit 01 交接檢討]] 與 [[game/content/files/reports/unit03_source_review|Unit 03 來源檢討]]。

### 周岑／ZHOU CEN

| 欄位 | 設定 |
| --- | --- |
| 年齡 | 36 歲 |
| 身份 | ORPHEUS 部署與安全研究員 |

## 六、文件簽名者與研究支援角色

### Y. LIN／林予安

- **身份：** 夜班檔案整理員。
- **為什麼參與：** 負責把不同研究員留下的紙本、終端輸出與封存副本整理成可追查的案件索引。
- **主要工作：** 核對檔名、頁數、建立時間、簽名與封存位置。
- **她發現的問題：** 同一件事可能被不同版本記錄；整理不能等同於刪除差異。
- **留下的痕跡：** Unit 01～16 的檔案索引與 [[game/content/files/archives/case_history_index|案件歷史索引]]。

### C. WU／吳承宇

- **身份：** 備份室操作員。
- **為什麼參與：** 確保 AI 的失敗與錯誤仍然能被復原與追查。
- **主要工作：** 備份、鏡像、復原演練與校驗。
- **他發現的問題：** 自動同步可能保存錯誤版本，也可能把原始差異一起覆寫；主檔案與鏡像必須分開保存。
- **留下的痕跡：** [[game/content/files/archives/mirror_checksum|鏡像校驗紀錄]] 與鏡像備份紀錄。

### J. WU／吳季衡

- **身份：** 控制室事故報告整理員，當晚負責 A 端資料。
- **為什麼參與：** 需要在設備故障時先讓研究團隊知道系統能否繼續運作。
- **主要工作：** 接收控制室警報、整理第一份事故摘要；沒有權限修改原始錄音。
- **他發現的問題：** 最先出現在控制台的時間與狀態不一定是完整事件；快速恢復和完整追查可能互相衝突。
- **留下的痕跡：** [[game/content/files/reports/incident_report_a|A 端事故報告]]。

### S. HSU／許思涵

- **身份：** 監控室事故報告整理員，當晚負責 B 端資料。
- **為什麼參與：** 負責比對多個監控終端，確認不同時間與狀態是否能同時成立。
- **主要工作：** 記錄同步差異、保留來源與時間，不直接選擇一個方便的版本。
- **她發現的問題：** 微小時間差可能改變研究團隊對 AI 行為的判斷；不能因為最後答案一致就刪掉形成答案的中間紀錄。
- **留下的痕跡：** [[game/content/files/reports/incident_report_b|B 端事故報告]] 與 [[game/content/files/logs/original_incident_timestamp.txt|原始事故時間戳]]。

## 七、角色設定維護規則

新增或修改 NPC 時，只處理以下問題：

1. 這個角色是人類、AI、系統功能，還是研究制度？
2. 他為什麼參與 ORPHEUS，或為什麼在 Unit 17 中介入？
3. 他目前正在做什麼？
4. 他在 Unit 17 前發現了什麼？
5. 他留下了哪些可被玩家交叉驗證的文件或操作痕跡？
6. 他的情緒是人類心情、AI 系統狀態，還是 ECHO 模擬出的語氣？

如果要處理玩家身份、玩家任務或玩家逐步發現，請改寫 [[02-1 玩家設定]]。如果要處理事件順序、角色在某個事件中的位置或 FILE 因果，請改寫 [[04-世界時間軸與故事主軸]]、[[05-完整歷史時間軸]] 或 [[03-歷史事件與文件關聯母檔]]，不要把劇情因果重新塞回角色基本資料。
