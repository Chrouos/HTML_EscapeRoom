# ORPHEUS／雙終端攻略

> 這份文件是測試與主持人用的完整攻略，包含劇情解答與 Terminal 權限路徑。正式遊玩時不要先給玩家看。

## 基本原則

- A、B 看到的檔案不完全相同；任何一端的失敗提示、私人提示、權限與 Terminal 變更，都只會留在該端。
- ECHO 的提示是方向，不是答案。先看檔案、時間、欄位差異，再和另一位玩家交叉確認。
- 文件閱讀器開啟檔案後會進入滿版閱讀模式；按檔名旁的 `←` 回到資料夾。

## 主線順序

1. **身份封條**：A、B 分別讀取自己的身份片段，交換兩端看到的欄位，再共同確認完整識別碼。
2. **電力復原**：查看案件摘要、系統索引與獨立事故紀錄，注意主控台時間與獨立來源的差異。
3. **樣本時間線**：比較紙本、封存索引與終端時間，不要用最後寫入的副本取代較早的紀錄。
4. **控制室授權**：讀取不同版本的出口／授權規章，保留共同覆核，不要因為單端顯示可用就直接執行。
5. **檔案庫復原**：先解開封存，再把兩端的碎片依原始順序拼回來；人工覆核欄位是關鍵。
6. **出口協定**：兩位玩家都要讀完各自的協定，交換缺失段落，最後共同完成覆核。

## Terminal 支線

所有操作都只能使用畫面提供的檔名或已授權的目標，不能輸入任意路徑，也不能自行提交檔案內容。

| 操作 | 條件 | 結果 |
| --- | --- | --- |
| `UNLOCK hidden_audit.log` | A 完成事故資料核對，取得 `incidentVerificationAttempted` | A 的私人資料夾出現隱藏稽核備註 |
| `DELETE local_mirror.tmp` | A 完成第二章並已取得稽核讀取權限 | 只刪除 A 端本地鏡像 |
| `RESTORE local_mirror.tmp` | A 已刪除本地鏡像且權限仍在 | 恢復 A 端本地鏡像 |
| `ADD recovered_note.md` | B 完成第二章並標記身份差異 | B 的私人資料夾新增恢復備註 |

刪除、恢復與新增都是角色自己的檔案狀態；另一位玩家不會在檔案樹、通訊或答案區看到這些私人操作。

## 圖片線索

- 控制室時鐘圖：提醒玩家獨立時鐘與主控台不是同一個來源。
- 撕裂紙片圖：提醒玩家注意紙本順序與缺頁，而不是只看完整副本。
- 夜班桌面圖：主要用來增加設施仍有人工作的故事感，也讓背景文件不會都像謎題。

若圖片載入失敗，文件仍會保留原本文字與圖說，不影響主線解謎。
