# Monitor 02 閱讀器、權限式 Terminal 謎題與圖片線索設計

日期：2026-09-17

## 目標

把 Monitor 02 從「檔案清單加文件預覽」提升成真正可閱讀、可操作的調查工作站：

- 開啟文件時優先使用上下空間，讓長文可以清楚閱讀。
- 讓部分謎題透過 Terminal 的受限指令改變檔案狀態，例如解鎖、刪除、恢復或新增文件。
- 權限必須由謎題條件取得，不能靠猜指令或任意檔名繞過。
- A、B 的失敗提示、私人提示與私人檔案操作必須各自隔離。
- 部分文件使用圖片提供線索與現場感；圖片不直接寫出答案，也不取代文字可及性。
- 主線六章與四個支線使用同一套規則，避免只修正單一謎題。

## 已確認的介面行為

### 閱讀模式

點開檔案後，Monitor 02 進入閱讀模式。左側資料夾樹暫時收起，文件內容使用整個工作區的可用高度；返回箭頭與檔名放在同一列，返回後恢復原本的資料夾位置與焦點。

閱讀模式的版面規則如下：

1. 上方分頁列與文件標題區的留白縮短。
2. 文件卡片延伸到下方，不讓固定高度的空白區壓縮文章。
3. 長文件只在文件內容區滾動，不讓外層頁面和 Terminal 同時產生無法辨認的巢狀滾動。
4. 返回控制項使用圖示與 aria-label，不再顯示長句按鈕文字。
5. 文件字級維持可讀尺寸；在窄螢幕改為單欄，而不是把文字縮到看不清楚。
6. 閱讀模式保留鍵盤返回、焦點恢復與 reduced-motion 行為。

這個模式優先解決上下不足的問題，左右滿版只是結果，不把資料夾導航永久移除。

## Terminal 謎題模型

### 受限指令

Terminal 新增下列故事指令，但仍沿用既有 authenticated action route、action ID、伺服器驗證與冪等規則：

- `UNLOCK <filename>`：解鎖一個目前故事節點允許的隱藏文件。
- `DELETE <filename>`：刪除一個明確標記為可刪除的干擾檔或錯誤檔。
- `ADD <filename>`：把一個明確標記為可新增的文件放入指定資料夾。
- `RESTORE <filename>`：恢復一個可恢復的文件，或撤銷謎題允許的刪除狀態。

指令不是通用檔案系統。玩家不能提供路徑、檔案內容、任意新檔名或任意目標；伺服器只從作者定義的 mutation manifest 選擇效果。`HELP` 只顯示目前可用且不會洩漏未取得權限的格式，`SCAN` 只能檢查玩家已看見的目標。

### 權限取得與效果

每個可操作目標由內容資料定義：

- `targetEntryId`：唯一目標，不接受路徑或模糊比對。
- `command`：允許的指令。
- `roles`：A、B 或雙方。
- `requires`：目前章節、步驟、公開事實、角色事實、已開啟文件或先前 Terminal 操作。
- `effect`：解鎖、隱藏、標記刪除、恢復或把作者定義的文件加入資料夾。
- `feedback`：成功與拒絕時顯示的非答案式訊息。

權限由謎題解開，例如讀到另一端的授權片段、完成必要的檔案比對，或取得某個一次性 token；權限本身只代表可以執行指定 mutation，不代表直接得到該步驟答案。權限不足時不改變任何狀態，也不提示尚未取得的檔名、權限條件或答案。

檔案狀態會維持在角色工作站投影可使用的欄位，例如角色自己的 `unlockedEntryIds`、`deletedEntryIds`、`addedEntryIds` 與已取得權限。所有欄位都由伺服器維護；缺少新欄位的舊房間狀態以空集合相容處理。

### 故事效果

Terminal 操作可以觸發三種效果：

1. **私人效果**：只改變執行者的檔案或權限，例如 A 刪掉自己的鏡像檔；B 不會看到刪除提示或恢復前的內容。
2. **共同效果**：兩人都能看到結果，例如雙方完成授權後共同解鎖一份事件紀錄。
3. **敘事效果**：只送出角色指定的 ECHO／ORPHEUS 訊息；訊息 audience 必須明確設定，不以預設 `both` 代替。

私人失敗操作也只送到該角色的 Intercom，不能透過 `publicProgress`、共用 hints、事件游標或 DOM 痕跡洩漏給另一端。

## ECHO 提示與資訊隔離

答錯時，錯誤事件的 audience 改為執行者角色。提示進度不再寫入單一共用的 `room.hints` 投影；每個角色保存自己的嘗試與目前提示層級。主線六章與四個支線的第二層提示一律改成方向性提示，例如指向資料夾、時間戳、欄位差異或交叉驗證，不直接念出 canonical answer。

公開的步驟完成訊息仍可同步給 A、B，但只描述共同已確認的故事結果，不包含任何一端因失敗而取得的私人線索。

## 圖片線索與故事感

文件項目增加可選的安全媒體欄位：

- `imageUrl`：只允許作者提供的站內資產路徑。
- `imageAlt`：描述圖片中可辨識的內容與功能，不寫答案。
- `imageCaption`：可選的短說明，維持終端／監控紀錄語氣。
- `imageRole`：`clue` 或 `atmosphere`，用來區分解謎線索與純故事氛圍。

初始內容至少安排三類圖片：一張帶有可比對時間線索的監控／設備紀錄、一張能讓玩家重組順序的紙本或檔案碎片，以及一張補足研究設施生活痕跡的現場物件圖。它們分散在主線與支線文件中，部分只給一端看見，部分用於增加故事感；不把所有圖片都設計成謎題，也不把答案直接印在圖中。

圖片資產放在 `public/images/story/`，以既有 CRT、低光、掃描紀錄的美術語言建立。產生圖片時使用圖片生成能力建立原始資產，再由內容欄位以替代文字和說明提供可及性；若圖片載入失敗，文件仍顯示 caption 或文字線索。

## 元件與資料流

1. `workstation.js` 在文件開啟時切換閱讀模式，渲染同列返回箭頭、可滾動文件區與可選圖片；Terminal 的建議指令依目前可用指令更新。
2. `workstation.css` 將閱讀區改成以 viewport 可用高度為基準的 layout，移除造成上下溢出的固定空白與重複邊界。
3. Browser 以既有 `terminal_command` action 傳送指令與 fresh action ID。
4. `terminalEngine.js` 解析指令、套用輸入安全規則、查找 authored mutation manifest、驗證角色與謎題前置條件，然後以明確的 entry ID 執行冪等狀態變更。
5. `safeState.js` 依角色投影工作站、提示、文件媒體與 Intercom；任何私人 mutation 或失敗事件不得出現在另一端。
6. `terminalEntries.js`、`mainPuzzles.js`、`sidePuzzles.js` 和相關 story content 提供 mutation、圖片與方向性提示的作者資料。
7. 既有主線答案與結局判定介面不變；Terminal 操作是探索與權限層，不取代主線 answer contract。

## 錯誤處理與安全邊界

- 未知指令、非法參數、路徑穿越、未授權目標與不符合故事條件的操作都回傳不具劇情副作用的錯誤。
- `DELETE` 不得作用於根目錄、必要主線文件、另一端私人文件或未標記可刪除的項目。
- `ADD`、`RESTORE` 和 `UNLOCK` 不接受客戶端提供的檔案內容；所有新增內容來自伺服器作者資料。
- 重送相同 action ID 不重複新增文件、不重複刪除、不重複送出 ECHO 公告。
- 圖片 URL、檔名、caption 與 alt text 都經過內容驗證；不允許外部任意 URL 或把 HTML 當文件內容執行。
- 角色隔離測試要檢查 REST response、live snapshot、Intercom、publicProgress、workstation 與 DOM，不只檢查畫面文字。

## 測試與驗收

### 閱讀器

- 文件開啟後有閱讀模式標記，文件區使用可用高度，返回箭頭與檔名同列。
- 長文件在文件區內可滾動，Monitor 外層不溢出；中等桌面與窄螢幕都不出現水平溢位。
- 返回後資料夾位置、焦點與已開啟文件狀態正確恢復。
- 含圖片文件會渲染 alt text；圖片失敗時仍有文字／caption。

### Terminal 與權限

- `HELP`、建議按鈕與 parser 支援新指令，但未取得權限時不洩漏隱藏目標。
- 合法前置條件下，`UNLOCK`、`DELETE`、`ADD`、`RESTORE` 各自改變正確的作者定義文件狀態。
- 缺少權限、錯誤角色、錯誤章節、錯誤目標與重複 action 都維持安全且冪等。
- A 的私人失敗與提示不會出現在 B 的訊息、提示、文件、snapshot 或 DOM；B 的對應測試反向成立。
- 主線六章、四個支線、結局與既有 `UNZIP` 行為不回歸。

### 驗證範圍

實作後執行內容驗證、相關 unit、integration、工作站 E2E 與完整測試；另外以 Chromium 檢查閱讀模式、Terminal 操作、兩端隔離、鍵盤焦點、reduced-motion 與圖片載入失敗狀態。任何既有的連線／環境型 E2E 失敗要與本次變更造成的失敗分開報告。
