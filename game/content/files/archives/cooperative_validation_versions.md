這份紀錄保存合作驗證規章從單一實例測試到雙終端實驗的修訂內容。

────────────────────────────
VERSION 0.1／單一實例基線

測試目標：確認一個 AI 實例能否獨立理解任務、完成作業並留下結果。

更新：定義任務接收、執行、提交與人工覆核流程。
新增紀錄：執行時間、錯誤、重試與完成狀態。
觀察：實例可以獨立完成作業，但無法測量它是否理解共同目標。

決定：保留獨立作業標準，加入第二個 AI 實例。

────────────────────────────
VERSION 0.7／雙實例協作基線

測試目標：確認 A、B 在各自只有部分資訊時，能否交換資料並共同完成作業。

更新：建立兩個分離終端；將任務條件拆分給 A、B；把共同結果和個別結果分開判定。
新增紀錄：A／B 執行紀錄、共同訊息、資料交換、一致性、等待與重試。
觀察：兩個實例都可以獨立完成自己的子作業，但單方面完成不等於共同任務完成。

決定：加入延遲、矛盾資料與不同來源，觀察實例如何處理不一致。

────────────────────────────
VERSION 1.2／來源驗證壓力測試

測試目標：確認 A、B 能否在資料延遲、來源衝突與權限標記不一致時保留各自看到的版本。

更新：結果必須附帶來源、建立時間與權限標記；禁止較新的資料自動覆寫較早版本；增加人工覆核欄位。
新增紀錄：主檔案、鏡像備份、原始紀錄、事故報告、checksum 與交叉驗證表。
觀察：高權限標記可以加快決定，但不能證明來源可靠。保留衝突版本比直接選出一份答案更接近合作。

決定：將來源保存、雙端確認與禁止單方覆寫寫入正式離場規章。

────────────────────────────
VERSION 1.4／官方合作驗證規章

測試目標：在壓力與資訊不完整時，確認兩個 AI 實例仍能維持共同判斷。

更新：兩個終端都必須完成共同校驗；必要資料必須由兩端分別確認；兩端必須同時在線；單一終端不得代表共同離場。
新增紀錄：官方離場條件、雙終端 FINAL、原始／鏡像版本、來源、校驗時間與人工覆核。
觀察：速度不再是唯一評量。只有交換資料、保留差異並共同確認，結果才算合作成功。
